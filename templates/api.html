Getting started

Every endpoint lives under /api/v1 and speaks JSON. Create a token under Settings → API tokens and send it with every request as Authorization: Bearer <token>. The examples on this page read the address and the token from two shell variables: 

DIREKT={{ origin }}
TOKEN=dkt_...

Then submit a download and follow its progress:

curl -X POST "$DIREKT/api/v1/downloads" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://example.com/files/movie.mkv"}'

curl "$DIREKT/api/v1/downloads?state=queued,downloading" \
  -H "Authorization: Bearer $TOKEN"
Authentication
A bearer token, or the web UI's session cookie. Tokens skip two-factor sign-in, so keep them secret and revoke unused ones.
Requests
Bodies are JSON with Content-Type: application/json. Unknown fields are rejected on most endpoints.
Times
RFC 3339 in UTC, e.g. 2026-10-21T08:30:00Z.
Sizes and speeds
Bytes, and bytes per second.
Errors
{"error": {"kind": "...", "message": "..."}} with a matching HTTP status; see Errors.
Unauthenticated
GET /healthz (health check) and GET /api/openapi.json.

Errors

A failed request returns an error status and a body such as {"error": {"kind": "not_found", "message": "download not found"}}. The message is safe to show to people; branch on kind. Malformed JSON, a wrong content type or an oversized body get the same shape, with the status that fits (for example 413 or 415). A 401 also carries WWW-Authenticate: Bearer.
